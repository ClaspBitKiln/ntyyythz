# Персонализация сайта и связка с SaaS

## Цель

Один домен `www.magicmet.ru` обслуживает два основных рынка:

- СНГ — приоритетное направление;
- Россия — отдельная версия в рамках того же домена.

Сайт не пытается «угадывать личность» посетителя. Он определяет наиболее вероятный сегмент по стране, языку, источнику перехода, поисковому запросу, просмотрам каталога и действиям на сайте, после чего показывает релевантное предложение.

## Структура одного домена

- `/cis/` — основная версия для стран СНГ;
- `/ru/` — версия для России;
- `/kz/`, `/uz/`, `/kg/`, `/by/`, `/az/`, `/am/`, `/tm/`, `/tj/` — индексируемые посадочные страницы по странам;
- `/catalog/...` — общая структура каталога;
- `/industries/...` — страницы по отраслям;
- `/services/...` — логистика, подбор аналогов, комплектация спецификаций;
- `/request/` — единая форма заявки;
- `/account/` или `/portal/` — будущая клиентская часть SaaS.

Каждая страна и товарная группа получает отдельный индексируемый URL, собственные title, description, H1, тексты, условия поставки и призывы к действию.

## Как определяется сегмент

Сигналы используются по приоритету:

1. Явно выбранная пользователем страна или регион.
2. URL страницы, рекламная кампания и UTM-метки.
3. Язык браузера.
4. Геолокация по IP только на уровне страны.
5. Поисковые запросы внутри каталога.
6. Просмотренные товарные группы, марки, размеры и отраслевые страницы.
7. Возвратные визиты по анонимному `visitor_id` после согласия на аналитику.

Автоматическая переадресация не должна быть жёсткой. При первом визите показывается предложение перейти на региональную версию, но пользователь всегда может выбрать другой рынок вручную.

## Что меняется для посетителя

### СНГ

- экспортные поставки с НДС 0% при выполнении условий;
- доставка до города, склада, терминала или границы;
- DAP/FCA/CPT и другие применимые условия;
- документы для экспорта;
- расчёт логистики в Казахстан, Узбекистан, Кыргызстан и другие страны СНГ;
- кнопка «Получить цену с доставкой»;
- форма с полями «страна», «город», «условие поставки», «валюта расчёта».

### Россия

- доставка по РФ;
- срочная авиа-, авто- и железнодорожная логистика;
- поставки на северные и труднодоступные объекты;
- подбор по ГОСТ, ТУ и чертежам;
- кнопка «Получить цену и срок поставки».

## Связка с SaaS

Сайт является верхней частью воронки. SaaS получает события и превращает их в лид, сделку и задачи менеджера.

### События сайта

- `session_started`;
- `region_detected`;
- `region_selected`;
- `catalog_search`;
- `search_no_results`;
- `category_viewed`;
- `product_viewed`;
- `delivery_calculated`;
- `phone_clicked`;
- `email_clicked`;
- `messenger_clicked`;
- `form_started`;
- `file_uploaded`;
- `lead_submitted`;
- `quote_requested`.

### Данные лида

- `visitor_id`;
- `session_id`;
- страна и город;
- выбранный рынок: СНГ или РФ;
- источник, UTM, реферер;
- просмотренные категории и товары;
- поисковые фразы;
- последний интересующий товар;
- файл спецификации;
- компания, имя, телефон, e-mail;
- желаемые условия поставки;
- оценка намерения купить;
- согласия на обработку данных и аналитику.

### Лид-скоринг

Пример правил:

- просмотр одной категории: +1;
- повторный визит: +2;
- поиск конкретной марки или размера: +3;
- просмотр логистики в свою страну: +3;
- загрузка спецификации: +8;
- заполнение телефона: +8;
- запрос коммерческого предложения: +10.

При достижении порога SaaS создаёт задачу менеджеру и уведомление на `m3@magicmet.ru`.

## SEO и персонализация

Персонализация не должна подменять индексируемый текст поисковым роботам. Для SEO создаются отдельные статические или серверно-рендеренные страницы по странам, товарным группам, маркам стали, размерам, услугам и отраслям.

Внизу страниц размещается структурированный перечень продукции с внутренними ссылками, а не бессвязный набор ключевых слов. Для каждой группы должны существовать отдельные посадочные страницы.

Обязательные элементы:

- `hreflang` для региональных версий;
- self-canonical для каждой индексируемой страницы;
- `sitemap.xml` с разбивкой по странам и категориям;
- schema.org `Organization`, `Product`, `BreadcrumbList`, `FAQPage` там, где это уместно;
- отсутствие скрытого текста и поискового клоакинга;
- единый переключатель региона в шапке сайта.

## Рекомендуемая техническая схема

- Next.js с серверным рендерингом и middleware;
- Supabase/PostgreSQL для посетителей, событий, лидов и каталога;
- API между сайтом и SaaS;
- очередь уведомлений для e-mail и задач менеджерам;
- Яндекс Метрика и собственная аналитика после согласия пользователя;
- Vercel, Netlify или Cloudflare с определением страны на edge-уровне.

Текущий статический прототип следует рассматривать как визуальную основу. Для персонализации, региональных SEO-страниц и двусторонней интеграции с SaaS проект необходимо перевести на серверно-рендеримую архитектуру.
