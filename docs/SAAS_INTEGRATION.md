# Интеграция сайта «Мэджик Металл» с AI Sales OS

## Роль сайта

`www.magicmet.ru` — публичный вход в воронку продаж: SEO, каталог продукции, рекламные посадочные страницы, поиск по маркам и приём заявок/спецификаций.

`AI Sales OS` (`ClaspBitKiln/SAAS`) — единый источник истины по компаниям, контактам, заявкам, расчётам, КП, коммуникациям и результатам сделок.

Сайт не должен становиться второй CRM и не должен дублировать в своей базе бизнес-статусы сделки.

## Целевая цепочка

```text
Поиск / реклама / email / Telegram
  → посадочная страница или карточка продукции
  → «Хочу купить» / звонок / отправка спецификации
  → сервер сайта валидирует обращение
  → server-to-server передача в AI Sales OS
  → создаётся или сопоставляется компания и контакт
  → создаётся заявка в стадии NEW
  → менеджер: расчёт → КП → отправка → результат
  → источник, UTM и история визита доступны в карточке заявки
```

## Граница ответственности

### Сайт хранит

- контент каталога и SEO-страниц;
- анонимную web-сессию до заявки;
- UTM, referrer, landing page, поисковый запрос;
- события поведения: поиск, просмотр продукции, CTA, звонок, начало и отправка формы;
- техническую очередь недоставленных обращений, только если AI Sales OS временно недоступен.

### AI Sales OS хранит

- компанию и контакт;
- заявку и её позиции;
- прикреплённую спецификацию;
- ответственного менеджера;
- стадии: новая → расчёт → КП → отправлено → результат;
- переписку, звонки, задачи, документы и историю сделки;
- связь с исходной web-сессией и рекламной атрибуцией.

## Интеграционный адаптер сайта

Публичная форма никогда не вызывает AI Sales OS напрямую из браузера.

```text
Browser
  → POST /api/leads на www.magicmet.ru
  → валидация, rate limit, honeypot, проверка файлов
  → LeadGateway
  → server-to-server API AI Sales OS
```

Контракт должен быть скрыт за интерфейсом `LeadGateway`, чтобы адрес и авторизация SaaS менялись через переменные окружения без переделки формы.

Рекомендуемые переменные:

```env
SAAS_API_URL=
SAAS_SITE_INGEST_TOKEN=
SAAS_TENANT_ID=
SAAS_SOURCE_ID=magicmet-website
```

## Правила создания заявки в SaaS

1. Идемпотентность по `externalLeadId` / `Idempotency-Key` — повторный запрос не создаёт дубль.
2. Контакт сопоставляется по нормализованному телефону и email.
3. Компания сопоставляется сначала по ИНН, затем по подтверждённой связи контакта; по одному названию автоматически не склеивать.
4. Создаётся заявка в организации, заданной `SAAS_TENANT_ID`.
5. Источник фиксируется как `magicmet-website`, отдельно сохраняются first-touch и last-touch параметры.
6. В timeline записывается событие `WEBSITE_LEAD_CREATED`.
7. Менеджеру создаётся уведомление; автоматическая отправка клиенту не выполняется без явного правила.
8. Вложение хранится приватно и доступно только пользователям соответствующего tenant.

## Надёжность

- таймаут server-to-server вызова: 5–10 секунд;
- максимум 3 повторные попытки с backoff;
- техническая outbox-очередь для временных ошибок SaaS;
- пользователь получает подтверждение только после надёжной записи в SaaS или outbox;
- каждое обращение имеет correlation ID;
- секрет SaaS доступен только серверу сайта;
- CORS не используется как механизм защиты server-to-server API;
- обязательны rate limiting, проверка MIME/размера файла и антивирусная обработка вложений.

## Аналитика воронки

Единые события:

```text
page_view
site_search
product_view
want_to_buy_click
phone_click
form_start
file_upload
lead_submit
saas_lead_accepted
quote_prepared
proposal_sent
won
lost
```

До отправки формы сессия анонимна. После создания заявки `sessionId` связывается с `requestId`, поэтому в SaaS можно считать полную конверсию:

```text
источник → посещение → интерес к товару → заявка → КП → сделка
```

## Что не делать

- не создавать отдельную полноценную CRM внутри сайта;
- не хранить стадии сделки одновременно в двух системах;
- не передавать SaaS token в браузер;
- не пытаться скрыто определять имя, телефон или компанию посетителя;
- не вводить Kafka, отдельный event broker или микросервисы для первой версии;
- не привязывать форму к конкретной внутренней структуре SaaS без адаптера и versioned contract.

## Этапы реализации

1. Сайт: внедрить `LeadGateway`, единую схему формы и атрибуцию.
2. SaaS: добавить защищённый tenant-scoped endpoint приёма website lead.
3. Добавить idempotency и timeline event.
4. Связать спецификацию с заявкой.
5. Провести contract test между двумя репозиториями.
6. Включить уведомление менеджера.
7. После пилота — статусные webhooks из SaaS в аналитику сайта, без дублирования CRM.
